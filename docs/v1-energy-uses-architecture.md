# V1 Energy Uses architecture

Current contract for the group-first Energy Uses workflow. Production code lives in [`v1/data/energy-uses`](../src/app/v1/data/energy-uses/); deterministic footprint calculations live in [`domain/calculations/energy-footprint`](../src/app/domain/calculations/energy-footprint/). Shared editing behavior belongs to [Data editing architecture](v1-data-editing-architecture.md), and writes follow the [workspace data workflow](data-access-and-workspace.md).

## Ownership and navigation

The inventory projects committed groups, including empty saved groups and a synthetic unavailable-group bucket for orphaned items. Cards expose equipment icons, member summaries, linked utility-group unions, and source/year availability without initializing records; notes stay in Setup Group. Browse restoration is independent of member selection.

The [route contract](../src/app/v1/data/energy-uses/energy-uses.routes.ts) is facility-owned at `data/energy-uses/groups/:energyUseGroupGuid`. Primary tabs are Setup Group, Energy Use Items, Group Summary, Group Footprint, and Facility Footprint. Setup Group is first in navigation; group landing restores the last successful account/facility/group member visit or the first alphabetical member, replacing history. Empty groups stay at `/items`. Group switching retains the active tab; `/table-results` redirects to Group Summary. Standalone item/History routes have no aliases.

The global sidebar stops at groups and the group switcher is facility-scoped. The item tab owns an independently scrolling icon/name rail, horizontal at narrow widths, containing every member regardless of inventory filters. Other tabs remain full width. Workbench outer corners follow appearance settings; internal sections have connected square borders. Guard peer changes and keep protected editors mounted if their saved item or group disappears. Creation/copy opens the new member. Item deletion selects the next alphabetical survivor, then the previous one, then the empty group. Synthetic groups allow orphan browsing/results, not metadata editing, group deletion, group-preselected creation, or automatic relationship repair.

## Setup and utility identity

One typed Settings session edits item settings and all explicit annual rows. Years are ascending and expose assumptions, amounts/units, overrides, estimates, and copy/remove actions. Global workspace status is separate from local Setup readiness. Derived consumption is excluded from draft equality; opening saved records never recalculates history. Mapping applies edited fields to the latest committed equipment record and preserves unrelated values. Calculators update the current typed draft; cancel leaves it unchanged. Retirement/reinstatement preserves stored history.

Creation chooses facility and an existing group or a named new group, then category/icon and item name. The Add Group naming choice precedes category selection. A new group and first item commit atomically with stable retry identity and open the created item's Setup, including creation launched from another group. Creation supplies existing source and previous-completed-fiscal-year defaults; detailed utilities, links, capacity, and annual values remain in Setup.

New utility configurations respect the two-source limit while preserving imported extra/duplicate rows. Source/year edits preserve untouched history, calculator inputs, copied amounts, and overrides. Removing saved sources or history requires review against current saved values. Source rows have no GUID: reconcile unambiguous source types and years, retain duplicate buckets, and block ambiguous configuration edits. Meter-group selection derives compatible utilities without overlapping source types; utility configuration and links change together after review. Manual utility selection can retain compatible links or explicitly review unlinking/history removal. Hydration never changes utilities from group membership. Selection drawers belong to one editor identity; item changes close them and stale confirmations cannot affect the replacement item.

## Group management and recovery

Setup Group edits name/notes through shared autosave and an allowlisted metadata command. Its equipment table contains every member with selection, linked icon/name, industrial system, utility types, and notes. Cells wrap without a horizontal table scrollbar; there is no search, pagination, Choose, Copy year, Remove year, or Clear selection action. The action row contains Add energy use, Add year, and Delete selected. Management requires settled, valid saved group settings; changing groups clears selection. Bulk deletion stays in Setup Group.

The item rail's accessible Add action preselects the current facility/group and opens creation at category selection. Transfer moves a settled item to another saved group in the same facility, including an empty group. It preserves GUID/local key, configuration, lifecycle, annual history/overrides, and meter links, changing only group relationship and modification time; the original group remains. Revalidate item, destination, and ownership in one transaction, then open the destination item.

Inventory Select groups works across matching pages and clears on filter/scope changes. Group-card and Setup Group deletion review complete saved membership, including filtered-out items; synthetic groups are excluded and empty saved groups are valid targets. Revalidate metadata, membership, and ownership inside one transaction, remove all reviewed groups/items, preserve linked meters/groups, and publish once. Setup deletion returns to the facility-filtered inventory.

Add year uses a shell-portal slideout with detached per-item drafts owned outside its view. Year choices combine valid meter/predictor/equipment years across the account; use the current calendar year if none exist and Other for typed input. Seed from each item's highest saved year or edit its existing destination year. Completed items precede the shared current form, remaining items follow it; direct selection retains drafts. Next validates without saving, skips reviewed items, and wraps. Save all validates every selected item and commits one annual-only batch when every other item is reviewed. Calculators reuse the annual form without replacing the portal.

Preserve other years/settings. Review year resets, discard, and reload; selective reload retains unaffected drafts and disposes replaced subscriptions, while changed facility settings reset all drafts. Revalidate all selected records, including skipped rows, their owners, and membership. Rejected writes retain drafts. Committed-write/publication failures block conflicting actions/navigation and recover by refreshing only, never replaying creation, transfer, annual updates, or deletion. Recovery state survives portal teardown and clears with its owning identity.

## Annual projections and results

The [annual projection](../src/app/v1/data/energy-uses/models/energy-use-projection.models.ts) resolves each saved source occurrence independently. An explicit year wins; otherwise carry its latest earlier saved amount forward with original source-year/unit/override provenance. Never infer backward, recalculate history, persist inferred rows, or fall back past invalid/ambiguous newer data. Retirement limits carry-forward after its last active year; explicitly entered later history remains visible. Missing/invalid sources remain unavailable, known partial totals are labeled, and zero-total percentages are unavailable.

Keep actual fiscal periods separate before aggregating facilities/groups/items. Group results use facility energy units; portfolio comparisons use account units. Horizons include intervening saved source/operating-condition years. Group Summary has session-only history state per account/facility/group; group footprints otherwise show the latest group year. Facility Footprint uses the later of the latest equipment year and latest complete utility fiscal year, or latest available utility year if none is complete. Inventory uses the latest scoped saved year before inventory filtering.

Group Summary shows equipment comparison bars, with Show history switching chart/table to stacked annual values. Equipment colors remain solid across entered/carried years. Its unpaginated, sortable equipment/year table defaults to latest consumption descending and includes every member and totals. Group Footprint uses source-to-item Sankey plus a source-grouped equipment table/subtotals; repeated source occurrences share one item/source contribution. Its latest fiscal year remains visible in print. Neither tab has a chart selector/year dropdown. Charts/tables retain original accessible values, coverage/provenance, zero/unavailable rows, canonical item links, and full-precision aggregation; display whole-unit amounts/percentages. Group tables reuse the shared results-table foundation, keep equipment names on one line, and use horizontal overflow only when content requires it rather than inner vertical scrolling.

Facility Footprint projects every owning-facility group/item at one actual fiscal period, including orphans, into source-to-group flows and a matching source-grouped table. Empty groups stay identified without fabricated contributions; group links open Group Footprint. Group results and equipment flows require no meter readings and perform no writes.

The shared facility results/balance services also supply lazy header facts: Metered Consumption, Equipment Use, Unaccounted/Over allocated, and Accounted for overall/by source. Canonical calendarization supplies included energy meters in site energy and facility units; exclude water, foreign, and excluded meters. Verify saved bill coverage and retirement rather than accepting padded zero months as known consumption. Missing/invalid bills cannot imply a complete balance. Subtract known equipment at full precision; label partial equipment coverage. Positive residuals become Unaccounted links, negative residuals warnings rather than negative chart links. Percentages require complete positive metered totals. Meter-group routing remains deferred.

During active refresh, retain the last coherent facility/year/unit snapshot with a compact calculation chip. Identity, units, or calendar changes invalidate it immediately; ready empty results replace it. A terminal meter error clears the old balance while current equipment results remain visible; retry restores canonical results. Facts are keyboard-scrollable in short windows and expand for print. Save feedback remains beside fields through the editor's own reload, reserves spinner space, and does not shift controls. Header source/validation chips summarize all committed group members independently of the selected tab/item.

Inventory Charts contains all matching items across pages in period/facility/group/item hierarchy, beginning at groups for facility scope. Its treemap-only slideup uses saved group colors, centered names/shares, a reset context band, and group headings for parent navigation. Backspace/Home provide focused keyboard alternatives; complete zero/unavailable/source data remains screen-reader accessible. Stale branches recover to root. Facility/account/group hover shares use full unfiltered known-equipment denominators; account shares are unavailable across incompatible calendars. Positive shares below 1% display `<1%`, exact zero displays `0%`; date ranges stay provenance rather than headings/hovers. Retain shell Escape, close, and focus return.

## Files and compatibility

Keep the existing equipment/group persisted shapes, GUID relationships, annual arrays, backup formats, calculations, and v0 behavior. Energy-use group membership is separate from optional utility meter-group links. Commands resolve current records when queued work runs, validate durable ownership/reviewed snapshots, commit compound operations atomically, and publish once. Backups preserve unresolved nonempty group GUIDs, remap included relationships, reject foreign ownership/collisions, and normalize missing optional meter links to `[]` without manufacturing relationships.

[Import architecture](v1-data-import-architecture.md) owns workbook detection and queue behavior. Footprint Tool mapping changes only upload drafts until reviewed commit, retains parsed identities/history/amounts, and clears facility-specific meter links when the facility changes. Repeated matching imports retain equipment/group GUIDs, local keys, and creation dates.

Export Excel reviews fiscal year/facilities in a shell slideout, defaulting to the current facility or all portfolio facilities and latest saved year. Export committed explicit rows independent of inventory filters/pages; never export carried-forward chart values. Pending/dirty edits block stale exports. Preserve the original workbook structure, validation, units, table, and filename. Prevent duplicate generation and suppress late delivery after account changes or teardown. More than two sources or invalid/nonfinite values reject the whole export without truncation. Old capacity codes and current display labels import; exports write display labels.

## Remaining acceptance

- Visually inspect a generated workbook in Microsoft Excel; automated fidelity and file-delivery checks do not satisfy this outstanding layout acceptance.
- Broader bulk reassignment/group-management policy remains future work. Same-facility transfer and reviewed saved-group deletion are implemented.
- Facility Footprint meter-group navigation remains deferred.
- A known inherited edge case closes an unfinished inventory creation draft if its facility disappears from the ready workspace; it was accepted as deferred follow-up.
- Historical native OS and print-dialog checks were not performed. Select future validation using [testing policy](testing.md) and the [validation workflow](../.agents/skills/validate-web-and-electron/SKILL.md), rather than treating past suite counts as current evidence.

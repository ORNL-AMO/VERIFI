# V1 visualization Dashboard and workbench

This reference owns browsing, creation, editing, navigation, repair, and preview lifecycle. Use [foundation](v1-visualization-foundation.md) for meaning/runtime contracts and planned Home reuse, [persistence](v1-visualization-persistence.md) for durable commands/transfers, and [utility visualizations](v1-utility-visualizations.md) for implemented resources, trace controls, presets, and capture.

## Dashboard and creation

Visualizations is enabled. Its account-owned Dashboard reuses resource cards, shared inventory detail levels, paging, sticky filters, and session browse restoration. Cards show derived ownership, categories, configured chart/period summaries, modification, and setup/reference status without requesting calculations. Search names, owners, and saved source labels; filter scope/data-source/setup/attention; sort modified, name, or attention. Folders, tags, favorites, thumbnails, bulk actions, and Recents remain pending.

Add and the saved workbench share typed decisions. Add collects Facilities, chart or preset, data categories, Meter selection method/resources when selected, Predictor and Energy Use selection when selected, Analysis result selection when selected, selected measures, then name. Account entry starts at Facilities with live All; facility entry preselects that facility and starts at Chart, with Back to review Facilities. Single-facility accounts retain this explicit entry distinction and do not initialize hidden analysis pairs. Facilities use searchable checkbox cards with All Facilities first. Selecting every current facility promotes to live All, including future facilities; at least one facility remains. Each current facility has a visible, keyboard-accessible Only action that pins a fixed selection, including when live All currently contains one facility. Double-click offers the same shortcut without first clearing presentation. The final selected checkbox cannot clear inclusion; All restores live future-facility inclusion.

Single decisions advance; multiple resources/categories require Continue. Reopening a completed decision preserves its descendants. Only actual dependency changes reset affected choices, with review when choices or incomplete input would be lost. Resources without readings remain selectable. Energy usage trend and Utility cost trend prefill this same flow, including Source, Meter group, and Individual meters paths. Cards distinguish facilities and retired meters. Meter setup defaults to Energy with calendarized monthly data; Add collects one or more supported measures before the name using the shared icon cards and selection markers; detailed display settings belong to the workbench.

The Add catalog offers Line, Bar, Area, Monthly patterns, Scatter, Correlation, Heatmap, Breakdown bar, Donut, Treemap, Sunburst, and Sankey and the Meters, Predictors, Energy Use, and Analysis categories. Unimplemented combinations retain coherent setup intent without fabricated resources/series. Mixed Meters/Predictors setup collects meter choices first and predictor selections next; monthly calendarized meter and predictor histories support unstacked Line/Bar/Area rendering without comparison. Each category has one shared resource selection and a set of measures; their supported resource/measure combinations generate separate traces. Energy Use-only setup defaults to latest saved fiscal year; other combinations use all saved history. Exact chart/source shapes and defaults belong to source contracts. There are no historical visualization decoders or upgrade adapters.

One creation proposal GUID survives failed save/retry and committed-publication recovery, then opens the saved workbench. Rename remains a simple form. Account routes use `visualization/dashboard` and `visualization/workbench/:visualizationGuid`. Facility entry filters Dashboard without retargeting intent. Session returns restore filters, paging/detail, scroll, and focus even when the new item falls outside them. Scope/account navigation resolves protected edits before changing context.

Meter Monthly Chart and Yearly Data captures open a single naming/confirmation slideout before durable creation. It contains the editable name and save/cancel controls without repeating chart settings; Save and open uses the visualization icon. The workbench offers View source chart while current chart intent matches the durable creation baseline, ignoring only the visualization name. Other edits hide it; reverting them restores it. New readings and facility fiscal-calendar changes do not hide it. Yearly source links include the captured Full year/YTD mode. The ordinary source link validates ownership and opens the originating chart anchor using normal leave protection. It persists across reloads without restoring source controls, zoom, scroll or focus. Missing or unverified origins omit the link; breadcrumbs remain the Dashboard navigation.


## Editing and guarded navigation

The workbench continues the same decisions: Facilities, Chart, Data Sources, one section per selected source category, separate trace sections, Dates and comparison, and Chart appearance. Data Sources offers four multi-select cards; adding a category opens a sibling source section and collapsing Data Sources does not hide it. Removing a category reviews all its configurations together; at least one remains. Resource selection, grouping and observation settings apply to every measure in that category. Reviewed source repair clears that category’s shared selection and dependent traces together; Analysis returns to one unassigned target per selected measure. Expanding/collapsing sections does not mutate saved intent; hidden mounted forms preserve independent incomplete drafts.

Source sections collect resources and measures. Meters shares Select by, resources, Meter Data To Chart and Data settings across its selected measures. Standard meter measures use calendarized data automatically, without an observation step or toggle. Bill charge selects the required bill-date view separately from monthly measures. Data settings contains aggregation and named-charge settings. Named trace sections are siblings of source sections: each supported resource × measure combination has independent type, axis, visibility, label, color, pattern and ordering. Trace ordering is global and follows the same sequence in settings, chart, legend and source data. Deselection removes affected combinations with existing presentation-loss review; Hide retains the trace for later use. No separate trace-exclusion state is saved. Current-owner explicit order precedes new matching members, dormant appearance survives live membership changes, and Reset order clears current-owner ordering including dormant entries. Chart-wide type changes review individual type exceptions; differing types yield Combination. Hidden/no-data traces remain configurable. When multiple facilities are included, meter and meter-group trace subdetails show the owning facility before type and axis, distinguishing same-named resources. Single-facility views omit that repeated context. The settings panel can hide without restarting the chart or replacing drafts/zoom. Printing omits settings and header actions.

Chart appearance owns one owner-relative or pinned unit per physical quantity, shared by all applicable traces, and the common Site/Source energy setting. Cost, percentages, emissions and predictor observations retain their canonical units. Saved Analysis energy values must already share a common Site/Source basis; changing the control cannot calculate a different basis. Existing chart/source compatibility limits remain authoritative.

Chart offers None, Absolute and Percentage stacking, with source/metadata/type/axis incompatibilities explained beside disabled choices. Value-dependent failures, such as negative percentage observations, are explained by the preview without rewriting intent. [Time-series presentations](v1-visualization-foundation.md#time-series-presentations) owns additive and denominator meaning. Legend visibility is saved; trace visibility uses saved item controls. All-hidden traces retain controls to restore them.

Time-series Chart appearance includes Smooth lines. The optional saved `chart.smoothLines` flag defaults to false when absent, preserving existing saved charts without a migration or read-time write. It changes line/area geometry only, retains gaps and values, and stays saved while items use bars. Capture preserves the monthly source chart’s smoothing preference. The smoothing setting itself requires no migration or viewing-time write; the current greenfield definition contract is described in the foundation.

Dates owns the Monthly/Yearly interval and the yearly Full year / Year to Date toggle. Selected ranges use month/year pickers with inclusive whole-month boundaries. There is no comparison editor or hidden comparison draft state; date edits save one period without comparison. Yearly calendarized utility charts expose both yearly modes here. YTD compares all saved years through one shared latest-data fiscal-month position for the included meters, independently of measure and trace visibility. Dates are constrained to all history without comparison; enabling YTD reviews discarded date/comparison settings or incomplete date input. Changing to an unsupported interval, chart or category reviews removing YTD. Its optional saved flag defaults false; actual bounds and cutoff context are runtime evidence. Source meanings belong to [utility visualizations](v1-utility-visualizations.md#yearly-data-and-year-to-date).

Monthly patterns uses either one Meters section with a single meter/group/source picker, one usage measure and optional Cost, or one Predictors section with one fixed predictor and a single panel. All-resource and mixed-category combinations are unavailable. Switching between Meters and Predictors reviews replacing the previous category. Groups and sources use canonical combined values and live matching membership. Its Years section replaces resource trace styling with linked year labels, colors, line patterns and visibility for both panels. The legend changes that same saved visibility. Dates offer only all history; exact meters, groups and predictors use their facility calendar, while source-based utility patterns use the chart owner’s calendar. Line smoothing is available, while stacking, independent axes, bar/area types and extra comparisons are unavailable. Chart/resource changes review incompatible presentation resets. Add supports the same configuration from scratch without assigning capture provenance.

Chart source-value tables are screen-reader content rather than visible collapsible sections. Keep chart interactions and meaningful unavailable/quality messages visible; hidden tables must not introduce invisible keyboard stops.

The renderer stays mounted while its current definition is reprojected, but pending old values are hidden until fresh evidence passes. Compatible appearance edits preserve zoom; changed data windows reset it. Zoom remains temporary and never writes source data or saved viewport state; there is no separate reset-zoom button. Account/definition switches and deactivation clear retained presentation. Presentation-only edits during current numerical work do not repeatedly restart the acquisition; the newest presentation is resolved normally from the existing session cache.

Typed reactive forms use serialized debounced autosave and submitted-revision acknowledgements. Preserve normalized-equivalent raw text and newer incomplete input on acknowledgement. Merge name/title/legend independently; conservatively group Facilities, sources, series, chart, period, and comparison. Typed period patches retain consecutive edits without restoring stale metadata, and reset/identity guards reject superseded callbacks. Linked consumers use committed definitions, never drafts.

Facilities changes flush coherent edits, pin their review to editor/workspace revisions and child input, then use the revision-checked same-identity retarget command. Every preparation forwards the saved record's durable reference blocks: a destination GUID collision cannot verify an imported binding or erase its presentation, while verified excluded siblings still prune normally. Ordinary autosave cannot change inclusion. Review only excluded resources/presentation or genuinely invalidated drafts; preserve compatible siblings and independent incomplete unit/date input. Live All tracks catalog changes without hydration writes. One included facility determines owner defaults/lifecycle; otherwise the account does. Pinned settings and explicit dates remain independent of ownership.

Distinguish rejected writes, conflicting authoritative snapshots, and committed-but-unpublished saves. Recover publication/read without replaying mutation. Navigation preflight owns shell-portal review across route guards and account/scope actions. Valid edits flush; invalid/failed/conflicting input offers Stay, applicable Retry/Review, and explicit Discard. Running writes and pending reviewed transitions block departure. Conditional unload protection covers unresolved session drafts; no durable draft journal exists.

## Facility analysis setup

Analysis uses a shared multi-select resource picker. Choices identify Account or the owning facility and retain exact saved GUIDs. Add requires one or more analyses and then collects measures. The workbench supports multiple selected analyses and, for each facility analysis, one or more result scopes (Facility total or applicable non-skipped groups). Every target receives every selected compatible measure, with an independent trace. New target traces reuse the existing measure/quantity axis, and trace subdetails identify the total or group scope. Account analyses supply Account total only. Browsing starts no result calculations. Missing identities remain repairable intent and are never selected by name; retained model configurations require explicit reviewed replacement.

Available measures follow the common monthly/fiscal-year interval and must be applicable to every selected target. Monthly actual results are the initial intent. Interval changes retain compatible measures and review discarded incompatible measures or dates. New selections share the first applicable saved unit per physical quantity and saved energy basis. Compatible display-unit conversions use the existing converter after canonical calculations; no Site/Source conversion or new formula is introduced. Result acquisition is shared across measures of the same target. Appearance remains qualified by target and measure, with unknown provider-local selectors dormant.

Monthly dates use Start month/End month and completed-month rolling controls. Yearly dates use all history, latest complete result fiscal year or one pinned fiscal year. Unsupported comparisons, ranges and conversions are explained without silently changing saved intent. Existing typed period drafts, conflict review, autosave, navigation protection and recovery remain authoritative. Current [facility analysis result semantics](v1-visualization-foundation.md#facility-analysis-results) own values, banking gaps, readiness and group fallback horizons.

## Account analysis setup

Under All Facilities, the shared multi-select picker offers saved account totals alongside facility analyses. Fixed facility inclusion offers only facility analyses. Valid single-facility accounts omit hidden account pairs from new choices. Account bindings offer the six [account result measures](v1-visualization-foundation.md#account-analysis-results) appropriate to the monthly/yearly interval and cannot select groups or separate banked measures.

New account choices require All Facilities. Existing incompatible bindings and appearance remain intact and explain how to restore inclusion or select another analysis; skipped facilities do not enlarge calculation membership. Switching account/facility targets uses the existing reviewed binding transition. Explicit supported defaults can remove an unsupported account group target, reviewing lost item presentation. Missing identities and transferred references retain the existing recovery rules and are never replaced by name or an active/paired analysis.

## Predictor setup

Add uses the same icon cards as Meters for multiple Standard/Weather selections. Cards show predictor names and facility names only when multiple facilities are included; full source context remains searchable and available on hover. Search appears for longer lists. Predictors without readings remain selectable. Cards toggle independently; Continue advances to Name. Completed selections can be revisited without reset. Skip for now saves setup-required intent, including an empty catalog. Math and Conversion placeholders are omitted from new selections.

All Predictors is an explicit live choice in Add and the workbench, available even with an empty catalog. It includes future Standard/Weather predictors in the included facilities, including retired and empty records; search only filters displayed choices. Existing fixed picks are never promoted to All automatically. Deselecting one member leaves All and saves the remaining current GUIDs; clearing All returns to setup-required intent. Membership changes do not rewrite the visualization. Sibling drafts/styles survive mode changes; explicit removal reviews affected customizations, while automatic departures retain dormant GUID overrides. Exact presentation declarations become dormant-capable overrides when switching to All, preserving active provider-ID fallback styling and nested dormant/foreign appearances.

The saved workbench uses the same compact resource picker as Meters, including All Predictors and guarded checkbox selection, followed by existing item appearance controls. Predictor section headers omit metadata summaries; individual trace headers show only their facility when multiple facilities are included. Adding a predictor retains sibling appearance and incomplete input. Removing a customized trace reviews its presentation and affected incomplete input, while retaining other traces and source/chart identity. Each new trace starts on the left axis; item settings allow independent axis changes. Source loss does not retarget by name. Unsupported saved source configurations remain readable and repairable through explicit selection/recovery.

When Predictors is selected, fixed ranges use Start month and End month controls without day inputs. Fiscal/comparison and incomplete-period controls are hidden, with retained unsupported settings explained and an explicit action to choose supported defaults. The shared period editor retains its conflict/draft lifecycle and meter-only controls. [Predictor observation semantics](v1-visualization-foundation.md#predictor-observations) owns the monthly values, ranges, units, provenance, and quality policy.

The workbench header shows the existing data-status chip and up to two issue summaries for the currently selected, owned meters and predictors, including current All/rule membership and live meter-group membership, with further issues collapsed. Actions open each affected source's existing data destination through guarded navigation. Findings cover full saved histories regardless of chart dates or trace visibility, using the workspace status service's current evaluation, preferences, and dismissals. Pending/unavailable evaluations never appear valid; account, revision, and selection changes reject obsolete findings/actions. Data status remains separate from saving/conflict state. The header reuses the shell's status evaluation without acquiring additional calculations. Reading-level provenance and omission evidence remain in runtime observations and chart tooltips. Chart-local data-check notices are omitted.

Add continues through meter configuration before predictor selection for mixed charts. Supported mixed previews retain existing assignments, default new traces to the left axis, and allow individual axis/type changes. Incompatible native, yearly, fiscal, comparison, or additional-source intent remains readable with explicit supported-setting controls; it is never silently converted. Empty sources retain gaps while usable siblings render. [Predictor observations](v1-visualization-foundation.md#predictor-observations) owns the shared window, units, and empty-state meaning.

## Equipment history setup

Add follows the Meter pattern: choose a selection method, choose resources, then name the visualization. Energy Use offers Energy use group, Equipment, Equipment type, Linked meter group and Facility. Equipment gives each selected item its own trace; other modes give each selected group/type/facility one combined trace and follow current matching equipment membership. Resource selection may be skipped to save incomplete intent after a method is chosen. New Energy Use-only Line/Bar/Area setup starts yearly, unstacked, with latest saved fiscal year. Other saved combinations remain intact and explain unsupported settings.

The workbench reuses connected Select by, resource selection and Data settings sections. Method changes review affected selections/presentation before clearing them; compatible unit/date settings and unrelated drafts stay protected. Pickers include empty saved groups/types/facilities, retired equipment and empty histories, disambiguate facility/group context, and retain missing GUIDs for explicit removal or repair. “Select current choices” selects the current resource list; it does not add future groups/types/facilities to that list. Matching equipment membership itself remains live. Reviewed facility-inclusion changes prune verified excluded facility selections and presentation; unavailable or blocked identities remain repairable intent.

Traces reuse label, color, axis, visibility and line/bar/area appearance controls. Resource changes preserve sibling presentation and review customized removals. Display units follow owner settings or pin a supported energy unit. The shared period editor offers Latest fiscal year, Pinned fiscal year and All history, retaining its protected invalid-input/conflict lifecycle. Unsupported saved ranges/comparisons remain explained until explicitly changed. The “Use equipment history settings” toggle lives in Data settings: enabling it reviews unsupported chart/source/period changes; disabling it keeps current values for manual editing. The manual toggle choice is local to the open editor; reopening derives its state from the saved configuration. No additional saved flag or history records are introduced. [Equipment annual history](v1-visualization-foundation.md#equipment-annual-history) owns projection, membership, coverage, units and fiscal-period meaning.

## Repair and deleted-draft recovery

Same-scope Duplicate creates independent identity. Reviewed copying proposes explicit included facilities, lists incompatible references to clear, and retains one creation identity across retry; never map by name. Current inclusion/ownership is derived from saved intent rather than stale envelope metadata. Readable missing-facility intent can repair through Facilities while ordinary edits remain disabled.

Reset readable missing/blocked resources only after review; retain reusable appearance/date/chart intent and clear dependent exact series/axis bindings. Readable transfer locks require explicit acknowledgement/removal of unverified relationships. Unknown formats remain read-only and backup-preserved, with diagnostics and confirmed deletion. Externally deleted editors remain mounted; Save as new reviews a stable proposal and discards the original only after acknowledgement. Protected recovery proposals veto navigation before another portal replaces their review. Incomplete child fields require an explicit discard decision; committed copies require refresh-only recovery.

Predictor repair reuses that reviewed reset: clear the affected source binding/presentation, retain compatible meter siblings and chart settings, then explicitly select a replacement. Renaming or adding a same-name record never repairs a fixed binding. Incomplete month fields remain local through source/item edits, rejected saves, retry, conflicts, and external visualization deletion. Save as new requires explicit resolution of those field drafts, keeps one proposal identity across failures, and recovers committed publication without repeating creation.

Energy Use repair follows the same review boundary for equipment, Energy Use groups, linked meter groups and facilities. Reset clears the affected source's fixed selections or equipment-type choices and dependent presentation, while retaining its selection method and compatible annual chart, period and display-unit settings. Empty current membership does not require reset; selected categories/anchors and their appearance remain available for returning members. Incomplete fiscal-year input stays local through navigation cancellation, configuration-conflict review and external deletion. Save as new requires resolving those field drafts before creating one stable replacement identity; committed-publication recovery never creates it again.

## Extension points and validation

Explicit source host branches are intentional. To extend a source, update its typed actions/projections and feature-owned item catalog, the Add draft/build/handoff in `LibraryLifecycle`, and the source branch/context in `WorkbenchComponent`. Register providers, shared dates, and presenters through `VisualizationsModule`/`PreviewRegistry`; source editors belong to the explicit host, not a generic editor registry. The shared configured-item dispatcher feeds decisions and chart summaries for every source family. Shared presentation lookup uses the same owner-qualified resource/provider precedence as rendering; feature projectors own membership, metadata and customization meaning. Source identity, unavailable meaning, and invalid draft/reset behavior remain feature responsibilities.

Shared period settings derive control choices, explicit defaults and retained incompatibility notices from one pure editor policy. Source-owned period checks remain authoritative; unsupported saved intent and incomplete form drafts are never normalized on hydration. The preview-owned date resolver and neutral civil-month helpers serve all sources.

Active previews alone request providers. Shared date context, exact capability checks, cancellation, and account/workspace/definition/edit/request identity reject obsolete results. Resource/item projection is feature-owned and calculation-free, so Dashboard summaries do not depend on decision execution. Pure transitions and editor tests cover parity, reset/reconciliation/save races, retry identity, source loss and unknown preservation. Native storage/backup/reopen plus keyboard/history/focus/rendering journeys cover runtime boundaries. Check themes, narrow layouts, complete accessible values and chart-focused printing; screenshot generation alone is not visual acceptance. Select commands/gates through [testing policy](testing.md) and the validation planner. Remaining adapters/chart breadth/Home belong to the [phase plan](v1-visualizations-and-home-plan.md).

# V1 visualization Dashboard and workbench

This reference owns browsing, creation, editing, navigation, repair, and preview lifecycle. Use [foundation](v1-visualization-foundation.md) for meaning/runtime contracts and planned Home reuse, [persistence](v1-visualization-persistence.md) for durable commands/transfers, and [utility visualizations](v1-utility-visualizations.md) for implemented resources, trace controls, presets, and capture.

## Dashboard and creation

Visualizations is enabled. Its account-owned Dashboard reuses resource cards, shared inventory detail levels, paging, sticky filters, and session browse restoration. Cards show derived ownership, categories, configured chart/period summaries, modification, and setup/reference status without requesting calculations. Search names, owners, and saved source labels; filter scope/data-source/setup/attention; sort modified, name, or attention. Folders, tags, favorites, thumbnails, bulk actions, and Recents remain pending.

Add and the saved workbench share typed decisions. Add collects Facilities, chart or preset, data categories, Meter selection method/resources, observation view, then name. Account entry starts at Facilities with live All; facility entry preselects that facility and starts at Chart, with Back to review Facilities. Single-facility accounts retain this explicit entry distinction and do not initialize hidden analysis pairs. Facilities use searchable checkbox cards with All Facilities first. Selecting every current facility promotes to live All, including future facilities; at least one facility remains. Double-click selects only that facility without first clearing its presentation.

Single decisions advance; multiple resources/categories require Continue. Reopening a completed decision preserves its descendants. Only actual dependency changes reset affected choices, with review when choices or incomplete input would be lost. Resources without readings remain selectable. Energy usage trend and Utility cost trend prefill this same flow, including Source, Meter group, and Individual meters paths. Cards distinguish facilities and retired meters. Meter setup defaults to Energy with calendarized monthly data; detailed measures/settings belong to the workbench.

The Add catalog offers Line, Bar, Scatter, Correlation, Heatmap, Donut, Treemap, and Sankey and the Meters, Predictors, Energy Use, and Analysis categories. Unimplemented combinations retain coherent setup intent without fabricated resources/series. Each category creates an independent local source identity. Energy Use-only setup defaults to latest saved fiscal year; other combinations use all saved history. Exact chart/source shapes and defaults belong to source contracts. There are no historical visualization decoders or upgrade adapters.

One creation proposal GUID survives failed save/retry and committed-publication recovery, then opens the saved workbench. Rename remains a simple form. Account routes use `visualization/dashboard` and `visualization/workbench/:visualizationGuid`. Facility entry filters Dashboard without retargeting intent. Session returns restore filters, paging/detail, scroll, and focus even when the new item falls outside them. Scope/account navigation resolves protected edits before changing context.

## Editing and guarded navigation

The workbench continues the same decisions: Facilities, Chart, Data Sources, selected source sections, Dates and comparison, and Chart appearance. Data Sources offers four multi-select cards; adding a category opens a sibling source section and collapsing Data Sources does not hide it. Removing a category reviews all its configurations together; at least one remains. Repeated saved source configurations remain intact until their category is removed. Expanding/collapsing sections does not mutate saved intent; hidden mounted forms preserve independent incomplete drafts.

Meter source sections contain Charted Data, selection/resources, Data settings, then one named section per configured item. Item type/axis/visibility/label/color/line pattern share one form; there is no Items wrapper, nested Trace/Style accordion, or reorder control. Chart-wide Line/Bar changes all item types and the default for new items; differing configured types yield Combination. Unsupported chart/category choices stay readable as setup/unavailable states. The independently scrolling settings panel can hide without restarting the chart or replacing drafts/zoom. Exact values and quality remain in a complete assistive-technology table; printing shows the chart rather than settings or a values disclosure.

Typed reactive forms use serialized debounced autosave and submitted-revision acknowledgements. Preserve normalized-equivalent raw text and newer incomplete input on acknowledgement. Merge name/title/legend independently; conservatively group Facilities, sources, series, chart, period, and comparison. Typed period patches retain consecutive edits without restoring stale metadata, and reset/identity guards reject superseded callbacks. Linked consumers use committed definitions, never drafts.

Facilities changes flush coherent edits, pin their review to editor/workspace revisions and child input, then use the revision-checked same-identity retarget command. Ordinary autosave cannot change inclusion. Review only excluded resources/presentation or genuinely invalidated drafts; preserve compatible siblings and independent incomplete unit/date input. Live All tracks catalog changes without hydration writes. One included facility determines owner defaults/lifecycle; otherwise the account does. Pinned settings and explicit dates remain independent of ownership.

Distinguish rejected writes, conflicting authoritative snapshots, and committed-but-unpublished saves. Recover publication/read without replaying mutation. Navigation preflight owns shell-portal review across route guards and account/scope actions. Valid edits flush; invalid/failed/conflicting input offers Stay, applicable Retry/Review, and explicit Discard. Running writes and pending reviewed transitions block departure. Conditional unload protection covers unresolved session drafts; no durable draft journal exists.

## Repair and deleted-draft recovery

Same-scope Duplicate creates independent identity. Reviewed copying proposes explicit included facilities, lists incompatible references to clear, and retains one creation identity across retry; never map by name. Current inclusion/ownership is derived from saved intent rather than stale envelope metadata. Readable missing-facility intent can repair through Facilities while ordinary edits remain disabled.

Reset readable missing/blocked resources only after review; retain reusable appearance/date/chart intent and clear dependent exact series/axis bindings. Readable transfer locks require explicit acknowledgement/removal of unverified relationships. Unknown formats remain read-only and backup-preserved, with diagnostics and confirmed deletion. Externally deleted editors remain mounted; Save as new reviews a stable proposal and discards the original only after acknowledgement. Protected recovery proposals veto navigation before another portal replaces their review. Incomplete child fields require an explicit discard decision; committed copies require refresh-only recovery.

## Extension points and validation

Explicit source host branches are intentional. To implement Predictors, Energy Use, or Analysis, extend the typed actions/projections and feature-owned item catalog, the Add draft/build/handoff in `LibraryLifecycle`, and the source branch/context in `WorkbenchComponent`. Register providers, shared dates, and presenters through `VisualizationsModule`/`PreviewRegistry`; source editors belong to the explicit host, not a generic editor registry. Extend configured item chart summaries when a new source supports trace types. Source identity, unavailable meaning, and invalid draft/reset behavior remain feature responsibilities.

Active previews alone request providers. Shared date context, exact capability checks, cancellation, and account/workspace/definition/edit/request identity reject obsolete results. Utility resource/item projection is feature-owned and calculation-free, so Dashboard summaries do not depend on decision execution. Pure transitions and editor tests cover parity, reset/reconciliation/save races, retry identity, source loss and unknown preservation. Native storage/backup/reopen plus keyboard/history/focus/rendering journeys cover runtime boundaries. Check themes, narrow layouts, complete accessible values and chart-focused printing; screenshot generation alone is not visual acceptance. Select commands/gates through [testing policy](testing.md) and the validation planner. Remaining adapters/chart breadth/Home belong to the [phase plan](v1-visualizations-and-home-plan.md).

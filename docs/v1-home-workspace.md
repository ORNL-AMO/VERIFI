# V1 Home workspace

Current Home navigation and dashboard editing contract for [Home3 #2914](https://github.com/ORNL-AMO/VERIFI/issues/2914). The [specification](v1-home-dashboard-spec.md) owns accepted design; [persistence](v1-home-persistence.md) owns durable records, commands and compatibility. Shared built-in/saved chart rendering, explicit customization, browsing controls and library saves are implemented; complete default compositions and supporting widgets follow the assigned Home phases through the [first usable Home milestone](v1-home-dashboard-plan.md#first-usable-home-milestone).

## Navigation and available templates

Home uses explicit account/facility saved identities in `home/dashboard/:dashboardGuid` and shipped identities in `home/built-in/:template/:version`. Default entry resolves once to an explicit URL so a later preference change cannot replace an open editor. Owners have independent sets, order and selected defaults; visible-order fallback never rewrites unavailable preferences. Missing, hidden and foreign dashboard URLs show recovery. A valid flagged single-facility account exposes only its sole facility set, without hidden analysis-pair initialization. Invalid configurations and stale account routes retain recovery.

The recipe catalog exposes Blank plus only provider-declared complete recipes. Template create/restore consume their complete blueprints; they do not construct partial starters. The initialization hook returns a set only when all six complete recipes exist, and entry never calls it. Opening an empty owner remains read-only, including initialized-empty sets. Imported nonempty sets without an initialized marker offer explicit adoption through the existing atomic command; adoption adds no dashboard or chart.

For a new owner, complete provider recipes resolve directly without writes. The first explicit owner choice captures the available built-in catalog; a saved customization shadows that exact template/version and carries a separately reproducible baseline with stable template keys. Initialized-empty/imported sets and deleted built-ins do not refill. Unknown shipped versions remain unavailable rather than substituting the current version. Production compositions remain unregistered until their complete Home6 delivery.

## Dashboard editing and recovery

Create, rename, duplicate, selected default, visible order, delete and template restore use typed `HomeCommands`. Draft forms and proposals are session-only and keyed by account/owner/dashboard. Editing captures saved dashboard/owner revisions. An active editor prevents account publication or dashboard/owner/route transitions until the user resolves its draft. Browser unload protection is conditional. Confirmation answers are bound to the draft revision; newer input cancels an obsolete answer.

Saving locks the submitted proposal. Rejected writes retain that exact proposal for retry, or permit deliberate draft review before preparing another proposal. Conflicts require loading and reviewing saved state, including a comparison of every changed persisted field (links, visibility, defaults and nested settings); keeping a local edit explicitly adopts the reviewed revisions without silently changing owners. Removing a dashboard/widget preserves linked charts and source data. Duplication copies independent layout/settings/widget identities while retaining chart links.

Restore confirms the named dashboard and owner, replacement of name/layout/widgets/saved defaults, preservation of identity/sidebar/default/visibility choices, creation of fresh recipe definitions, and retention of former charts. Routed confirmations use the shared modal portal and confirmation dialog, including canceled-dialog focus restoration.

A committed publication failure retains its receipt across departure. Pending saved changes have an account-local recovery inbox, independent of the active owner/dashboard URL, so first creation/default redirects, deletion and hidden destinations cannot strand receipts. Recovery calls `HomeCommands.recover` and never submits a mutation again or navigates to a departed selection. Rejected drafts and receipts are not durable journals; browser reload protection cannot guarantee recovery after an unconfirmed process termination.

## Presentation boundary

Known unavailable widget references and unsupported formats retain truthful placeholders; a coincident imported GUID does not verify blocked intent. Notes remain plain text. Chart widgets use the same provider/date/presentation registrations as Visualizations. Built-in energy/water rolling-improvement configurations render directly without library records; explicit saved links read committed definitions. Context labels distinguish live reporting from exact named analyses and retain source scope. Missing/unsupported references remain unavailable; actions, goal summaries and account facility-progress rows consume existing status and reporting-analysis owners. Overview-report creation remains unavailable. The layout editor exposes notes, existing saved visualizations, the required energy/water reporting rolling charts and typed internal shortcuts. Active chart views acquire data; layout editing deactivates chart demand. Typed controls resolve explicit widget overrides before opted-in dashboard browsing/defaults, then base configuration. Unsupported requests retain their intent and explain recovery to base settings. All supported persisted widget variants retain title, Half/Full size, order, settings and truthful states; later data widget renderers are not advertised as available additions.

## Display exploration, library saves and return

Dashboard browsing is isolated by account session, owner and dashboard identity; it survives chart open/return and routes away/back, and resets on account-session changes or reload. Invalid month input stays local while the last valid request remains active. New date ranges use inclusive whole months; unrelated edits preserve exact existing civil bounds. Inherited latest-data rolling windows share the newest eligible active history across participating widgets while retaining each chart’s source scope. An empty eligible union stays an explained empty window. Units use the existing converters; Site/Source applies to utility energy, analysis basis stays fixed, and Market/Location changes only supported emissions requests. Source inclusion and identity never change through filters. Unchanged sibling configurations retain their active preview.

Save as dashboard defaults uses the protected dashboard proposal and creates no library item. Widget overrides/inheritance and unfinished replacement selections participate in the same draft/leave protection. Explicit same-account replacement reviews source scope and acknowledges only that widget's blocked paths. Saved links open their shared workbench for source repair. Built-in reporting setup remains an owner Analysis selection; it never creates a hidden analysis.

Save as visualization first opens a named library draft. Explicit confirmation uses the ordinary visualization command boundary with captured Home owner/dashboard revisions and source identity checked inside the native transaction. Stable proposals retain their identity after rejection; committed publication recovery refreshes without another creation. Success creates one independent reusable definition, preserves reporting/period meaning and leaves the Home widget built-in. Cancel creates no records. A pending library draft blocks departure until saved/canceled; a committed receipt requires refresh.

Opening a linked chart remembers a typed session-only Home destination and current scroll/widget. Return to Home validates current ownership and view availability, restores browsing and focus, or resolves the owner's current default/creation guidance after deletion. Account changes clear the token. No arbitrary return URLs are accepted.

Print uses committed order/defaults while retaining the editor draft. Ready accessible alternatives are cached only for the identical definition and committed snapshot, so layout editing can print already-acquired committed values without showing draft results. A changed source/snapshot invalidates that alternative; current loading/unavailable states remain truthful.

## Widget drafts, layout and accessibility

Widget title, plain note text, typed shortcut choice, order and Half/Full size participate in the dashboard's protected draft. Add/remove never writes a saved visualization. Linked additions start with dashboard inheritance off and preserve source scope/settings. Duplication retains the same chart links while allocating independent widget/layout identities. Explicit shortcut selection may acknowledge only that widget's reviewed blocked paths; rename, movement and sizing never acknowledge references. Unfinished add-widget target choices survive workspace reload and block saving until added or cleared.

Every widget has labeled Move earlier/Move later and Half/Full controls alongside pointer handles. Removal confirms draft-only consequences and preserves saved charts/source data; focus moves to the next widget or Add widget. Creation focuses the new editor, movement focuses its heading, and canceled confirmations restore the opener after the routed workspace becomes interactive.

Array order drives DOM, reading, keyboard and grid order. Sparse row placement never backfills gaps or visually repacks the sequence. Two columns require at least `52rem + 4px` of container width, leaving each Half widget 24rem of content after padding and borders; otherwise every widget stacks. Controls wrap, long names/text break safely, and workbench borders connect with square outer corners and no vertical gaps. The main dashboard-order links remain available when the sidebar is collapsed.

Print switches to committed widget order/content and the committed dashboard name, in one column, without changing the retained editing draft. Editing/navigation controls are omitted; notes, shortcut labels and truthful deferred/unavailable states remain readable.

Chart alternatives contain complete shared-presenter values for assistive technology and expand into readable tables when printing. Account/dashboard/widget/source identities bound preview lifetime; obsolete results never replace current context. Pending analysis calculations are shared across active consumers by authoritative input fingerprint and canceled when the last consumer leaves.

## Actions and reporting goals

Owner actions consume active v1 To-dos and existing preferences/destinations, with errors before warnings and stable source order within severity. Every action remains reachable through paging; print includes all matching actions. An empty ready state requires successful current evaluation.

Goal summaries keep goal settings and reporting readiness independent. Missing or invalid goals link to owner Settings; unavailable reporting choices link to scoped Analysis without a fallback. Facility progress includes every currently owned facility and its own reporting selections, including unavailable rows. Explicit category settings can include energy and water; older per-measure settings retain their meaning. Account-analysis charts retain their own selected-child roster.

Latest finite authoritative rolling improvement retains its through-date, units/basis, partial-input evidence and current calculation provenance. Goal and analysis baselines remain distinct. Target attainment requires a positive valid goal and a finite result without missing-input warnings, and remains signed/unclipped. Two shared analysis Worker slots bound active demand; obsolete context is canceled and cannot publish. No view creates goals, reporting choices, dashboards, charts or hidden analysis pairs.

# V1 report architecture

The existing account/facility Reports workbench owns inventory, lifecycle, routes, common editing, navigation protection, and stage presentation. Individual report migrations supply their settings, applicable checks, and in-app content. Better Plants is the first implemented account report; see [#2804](https://github.com/ORNL-AMO/VERIFI/issues/2804).

Account report Setup ends with a Delete report action using the existing report deletion command and shell confirmation portal. Confirmation pauses autosave and permits deletion of incomplete drafts. Cancel or failure preserves the draft; only a committed deletion discards it and returns to the account Reports dashboard. The workbench owns the deletion coordinator so removing the selected report can unmount Setup without interrupting the return navigation. Analyses, source data, and other reports remain unchanged.

## Ownership and extension pattern

- Keep each report in its owning feature folder. The existing routed Setup, Data Checks, and Report components compose report-specific components; unmigrated types keep their explicit placeholders.
- Shared report stage surfaces use the current appearance radius for their bottom outer corners while preserving connected section borders.
- Reuse `ReportAutosaveController` for scheduling and protection. A feature editor owns a typed draft and translates only explicitly edited fields into a setup command. Handlers merge with the latest durable record and publish the full affected-record patch after commit.
- Keep input preparation and deterministic checks/calculations under `domain/reports`; platform owns Worker messages, teardown, and SHA-256 hashing. `AnalysisReportCalculationService` supplies the existing two-minute Worker timeout and the synchronous fallback.
- A route-scoped coordinator owns demand, current results, errors, and retry. Shared report state vocabulary and form-surface CSS live under v1 shared reports. Components render prepared values rather than starting Workers or querying repositories.
- Separate pure presentation projections from rendering. Better Plants consumes the existing `BetterPlantsSummary` contract and builds form rows without rounding calculated values. Future print/file adapters can consume those results separately from the DOM.
- Resolve report identity icons through the shared [`reportIcon`](../src/app/v1/shared/reports/report-icons.ts) lookup. It maps account and facility types separately and falls back to the existing page icon until a custom design is available. Cards, sidebars, workbench titles/switchers/stages, and analysis linked-report rows share this presentation metadata; icon names are never persisted. Follow the [custom-icon guide](../src/app/v1/shared/icons/README.md#report-icons) to add another report design.

This is an extension pattern, not a dynamic report-authoring framework. Add common capabilities only when an implemented report needs them.

## Data flow and calculation lifetime

One committed account workspace snapshot supplies the selected account analysis, owned facilities and facility analyses, transitive banking dependencies, meter readings, and relevant predictor inputs. Single-facility reports preserve their saved hidden account-analysis GUID while resolving the underlying facility analysis as the review owner. Reading a report never creates or repairs pairs; use the existing explicit link-selection/refresh command.

Setup computes review freshness and can reuse cached checks without starting a checks or report Worker. Better Plants Data Checks requests model validation only for the selected report year, independently of **Include all years**. Report generation starts only after that year's current checks are clean or its matching review receipt is available, and current workspace/report validation permits calculation. Direct Report entry enforces the same selected-year gate. All-year output still runs newest first, excludes the baseline itself, and is bounded by the loaded meter history. Changing output-year coverage cancels stale report work and immediately hides its pages without invalidating current selected-year checks; changing the selected report year invalidates both checks completion and displayed pages.

Setup's analysis inspection buttons reuse the account and facility dashboard detail slideouts and their demand-driven outcome coordinator. Only the inspected analysis requests outcome results, and closing the slideout cancels that demand. Inspection does not change the report link; **Select for report** updates the existing typed draft and uses normal autosave. Account and facility active-reporting selections remain independent.

The shared detail status box contains validation findings and suppresses stale findings while checks are pending or unavailable. Account inspection reuses the Select Facility Items candidate projection for status, group methods, and Data Through, alongside saved modification dates and the summary card's valid/total selection count. Tables adapt to narrow slideouts without horizontal scrolling. Shared linked-item rows identify report types with icons and preserve analysis and banking dependency identities. These views read the workspace without requesting additional result Workers or changing selections.

**Go To Analysis** saves pending report edits and opens the inspected analysis without selecting it. A GUID-based report origin supplies **Return to Report** in both analysis workbench headers. The route-scoped [return service](../src/app/v1/shared/reports/report-analysis-return.service.ts) revalidates the owning account and available report, carries validated origin query parameters through stage links, footer navigation, result/group tabs, prerequisite redirects, and account-to-facility drill-ins. Reloaded analysis URLs therefore retain the same report return and read-only entry behavior. Returns save pending analysis edits and use canonical report Setup routes and the existing navigation guards. Missing or unavailable reports suppress the return action. Report-origin facility entry validates the target owner and skips automatic hidden-pair repair, including for an inspected analysis that is not selected for the report.

Analysis selection filters narrow the cards by category and baseline year without changing the selected analysis or saving report edits. The type filter appears only when the account contains both energy and water categories. Filters reset when switching reports, and a selected analysis hidden by the filters remains linked and is identified above the cards.

The coordinator retains only its current checks and report results. Changes to account/report identity, readiness, operation, or checked content cancel obsolete work. Report calculation freshness additionally covers all prepared meter inputs, including additional water outside the intensity calculation, and facility manufacturing classification. The coordinator uses fresh prepared report inputs independently of cached checks, so those report-only changes refresh values without invalidating a current analysis review. A synchronous state projection hides old results before Observable scheduling can publish another result. Changes to names or report notes reproject presentation without regenerating calculations. Hashing participates in Angular pending-task tracking; Worker unsubscription, error, timeout, and completion terminate the Worker.

## Explicit shared analysis review

Clean checks complete automatically without writing a receipt. Visiting Data Checks never acknowledges issues: users check the shared footer acknowledgment beside Continue to explicitly save review. Model issues at any severity, failed validation flags (even when legacy notes are absent), and report warnings require acknowledgment; informational findings alone do not. Critical model issues, blocking report/analysis findings, empty results, and missing requested periods prevent completion and acknowledgment. Continue remains disabled until completion; pending and completed status is shared by the header, stage indicator, and footer. A report that still requires review shows a Data Checks action instead of values.

Account and facility analyses have an optional `dataCheckReviews` array. Each receipt records the checks version, report year, SHA-256 input fingerprint, and confirmation timestamp. One receipt is retained per checks version/year. The receipt belongs to the account analysis for portfolios, or the underlying facility analysis for single-facility workspaces. Matching reports share it, independently of their names, notes, or content visibility options. Better Plants acknowledgment covers only the selected report year, including when earlier report pages are displayed. Existing historical receipts remain compatible and are preserved, but cannot substitute for the selected year's receipt.

The fingerprint includes the review owner, reporting year, baseline, effective calculation settings, selected facility/group analyses and models, banking dependencies, relevant meters/readings, and predictor inputs. String `id` values on analysis/model predictors are GUID references and remain part of the fingerprint; only numeric local `id` keys are excluded. It also excludes receipt metadata, names, contact details, and display metadata. GUID collections are canonicalized; coefficient and predictor ordering is preserved. Unused regression candidates and meters outside the included/banking groups do not invalidate review. Older receipts that omitted predictor references become stale naturally when the current content is hashed; their stored shape remains compatible.

Acknowledgment computes and validates the displayed checks before opening an IndexedDB transaction. The transaction rereads the complete dependency set, synchronously compares its canonical content with the displayed content, merges receipts into the latest analysis, and commits atomically. Asynchronous hashing never occurs inside a native IndexedDB transaction. A changed dependency or failed write prevents confirmation and publication.

Absent receipts mean unreviewed; completion can still be established by current clean check results. This optional addition needs neither a record backfill nor an IndexedDB schema/data-version increment. Backups can carry the optional metadata; import clears it after GUID remapping. Analysis copies clear receipts. Copying a report can reuse review of its unchanged analysis. Legacy `isAnalysisVisited` and `dataCheckedDate` remain separate and are not advanced by report navigation or acknowledgment.

## Reusing analysis checks in another report

- Construct `AnalysisChecksController` from the shared v1 reports layer in the owning workbench injection context, as with `ReportAutosaveController`. Keep one instance per workbench; do not provide a global controller.
- Supply a reactive `AnalysisChecksRequest`: a stable report/context key (unchanged during pending writes), readiness or error, prepared `AnalysisReportInputs`, requested validation years, canonical-owner receipts, and current blocking/warning findings. Validation years can differ from generated output years; the report adapter owns that policy. Demand is `freshness` in Setup, `checks` for the Data Checks page, and `gate` before generating report values.
- Supply an explicit persistence callback receiving the displayed `AnalysisChecksResult`. The report adapter owns selection and commands; it must await transactional receipt saving and committed workspace publication through the existing command boundary. A successful callback alone never fabricates reviewed state.
- The controller owns versioned content fingerprints, current checks, cancellation, bounded caching, completion, saving, and retryable failures. Report-specific result calculation remains outside it and runs only when completion permits it. Never equate `reviewed` with `completed`: clean checks complete with no review receipt.
- Render `AnalysisDataChecksComponent` with checks, findings, and current facility/group labels. It presents one Issues summary with severity totals and a card for each facility/group with issues, combining its affected reporting years and using its highest severity for the card color, followed by an Executive summary across all years, with always-visible comparison tables grouped by reporting year and analysis method. Regression tables show facility/group identity, model year, variable p-values, R², adjusted R², model p-value, formula, and minor issues. Per-row controls and issue links expand the relevant predictor validation table inline without hiding model comparisons.
- Pass the controller's `workflow` to the optional shared header status and `AnalysisChecksAcknowledgmentComponent` in the workbench footer. Handle its typed `acknowledged` output with `confirmReview()`, and use `workflow.completed` for Continue and stage completion. Keep navigation in the workbench. Saving disables duplicate acknowledgment; failure restores the unchecked control; successful keyboard acknowledgment moves focus to the completion message before Continue.
- Better Plants supplies the first adapter. Pending report migrations retain their existing placeholders until they supply their own input/period/command adapter; shared checks do not inspect Better Plants settings or account/facility workbench contexts.

## Better Plants presentation and compatibility

Energy and water reports preserve the current program calculations, selected data, source/site conversions, units, fiscal-year treatment, precision, optional sections, notes, and saved report configuration. The official banner, footer, and form relationships remain, with v1 theme tokens, accessible tables, wrapped notes, and horizontal table overflow at narrow widths.

The in-app preview adds space above the first report and between yearly reports. Facility performance uses a compact table with horizontally and vertically centered cells, adapting to the available width.

Inventory snapshots mark Better Plants content as implemented, so its cards omit the pending-content notice at every detail level. Other report types retain that notice independently of setup readiness.

Two existing presentation/calculation quirks are deliberately characterized rather than corrected in this migration: facility-performance bands use strict inequalities, excluding exact band endpoints; the legacy water participation table places report-year counts in its first numeric column and baseline-year counts in the second. Any correction needs a separate reviewed behavior change and output parity work.

Per maintainer direction, this migration covers setup, checks/review, and in-app display. Printing and file output remain separate work under [#2791](https://github.com/ORNL-AMO/VERIFI/issues/2791) and subsequent output tasks. Existing v0 calculations and writers remain functional; production v1 does not import v0 UI.

The account report stage footer shows disabled PDF, PowerPoint, and Present actions as placeholders for that output work.

## Verification

Protect deterministic input selection, review freshness, model checks, form projection, and autosave with fast tests. Use Chromium for Worker messages, transaction rollback/stale-review rejection, reopen/backup behavior, and the complete review/display/invalidation journey. Inspect the form at practical desktop and narrow browser widths in light, dark, and high-contrast themes. Follow the [repository validation policy](testing.md) and validation planner for parent checks.

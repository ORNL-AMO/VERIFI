# V1 Visualization Dashboard and Workbench

Accepted implementation specification for [Vis3 / #2904](https://github.com/ORNL-AMO/VERIFI/issues/2904), following the [foundation](v1-visualization-foundation.md) and [persistence](v1-visualization-persistence.md). This is framework-first delivery within the [Visualizations and Home plan](v1-visualizations-and-home-plan.md).

## Dashboard and creation

The [Vis4 utility extension](v1-utility-visualizations.md) now supplies real utility source/period editors, protected invalid-field review, line/bar rendering and settings, explicitly bound energy/cost recipes, and faithful inventory capture. Other chart/source combinations retain the framework's setup/unavailable behavior. Definition v2 includes display visibility/overrides and the consolidated data-source contract; storage envelopes remain unchanged.

Use the Reports/Analysis card dashboard, shared inventory detail levels, paging, sticky filters, and session browse restoration. Show ownership in the shared card header, matching Reports: account cards say Account visualization, facility cards show the linked facility name, and the card body does not repeat ownership. Show one labeled-on-hover, screen-reader-named icon per selected data-source category instead of source-name chips; use the same icons at every detail level. Show concrete chart/period summaries, modified date, and setup/reference status without calculating Dashboard items. Search names, owners and saved source labels; filter scope, data source and setup/attention status; sort modified (default), name or attention. No folders, tags, favorites, thumbnails, bulk actions or Recents.

Add visualization collects ownership, concrete chart type, one or more data sources, then name in stepped selection cards. Reuse Meter/Predictor editable selection chips and step-specific focus: single choices advance immediately, while the multiple-source step requires Continue. Opening a previous selection immediately clears every later choice, including the draft name, while retaining the selection being edited. Reopening ownership clears facility/chart/source/recipe details; reopening a facility clears chart/source/recipe details; reopening a chart clears source/recipe details; reopening recipe grouping clears selected resources. Locked preselected ownership remains non-editable. A named facility entry keeps its current preselected/locked ownership; single-facility accounts skip ownership selection. The section remains Visualizations; the sidebar destination and return actions say Dashboard. The Dashboard route is `visualization/dashboard`; internal branch names remain unchanged.

Custom creation offers Line, Bar, Scatter, Correlation, Heatmap, Donut, Treemap and Sankey. The shared [data-source catalog](../src/app/v1/visualizations/visualization-data-sources.ts) offers Meters, Predictors, Energy Use and Analysis. Require at least one category and create one independent setup source per selection. Predictors includes standard and saved weather predictors; Analysis contains result and model modes rather than separate categories. Cards deduplicate category icons, and the Data source filter matches any included category. Selecting categories does not prove rendering compatibility. The workbench can add repeated sources from any category and remove individual sources. Concrete Predictor, Energy Use and Analysis editors/providers remain downstream; unavailable editors retain explicit setup-required feedback.

Commit an incomplete definition through Vis2 before opening the saved workbench. Preserve one proposal GUID and the complete selected chart/source intent across failure/retry; recover committed publication rather than replaying a committed create. Rename remains a simple name form. Single-facility accounts create only facility-scoped items with no scope picker. Existing portfolio items remain visible and unchanged. Scope-changing copies obey the same destination restriction. Duplicating a retained portfolio item in a single-facility account opens explicit reviewed copying to the sole facility; invalid single-facility setup blocks either copy entry.

Chart defaults are native/unstacked time series, disabled Scatter fit, raw signed correlation, month-year linear heatmap, absolute composition values, unassigned treemap hierarchy and energy-balance Sankey. Scatter X/Y bindings may be absent until actual series are selected; supplied malformed bindings remain invalid. Setup creates no invented series or resource identities. Only Energy Use alone defaults to the latest saved fiscal year; all other combinations start with all saved history and await adapter period review.

The current greenfield definition contract is updated in place: source kinds are `utility`, `predictor`, `energy-use` and `analysis`. Meters retains the existing `utility` adapter key and calculation behavior, including grouping by meter group, utility source or individual meter. Analysis uses a required `mode: 'result' | 'model'`, with mode-specific measures and model references. New Analysis setup defaults to result/actual without fabricated resource or model identities. Predictor standard/weather identity comes from selected records, while resolved observations retain their distinct provenance. No compatibility aliases or migration are provided for obsolete visualization source kinds; database stores, record envelopes and backup envelopes are unchanged.

Canonical account routes are `visualization/dashboard` and `visualization/workbench/:visualizationGuid`. Facility entry opens the Dashboard's facility filter. Browsing another scope never retargets a saved definition. Session return context restores originating filters, paging, detail, scroll and focus even if the created/copied item is outside them. Scope switches resolve edits then open the target Dashboard; account switches resolve edits before selecting/publishing the new account. Single-facility visualization entry must not initialize hidden analysis pairs.

## Workbench and save lifecycle

Connected Data Sources and Appearance sections sit beside persistent preview; narrow screens stack controls first. Edit name, display title and legend initially. Source/period/chart summaries show every selected category and the concrete chart, preserving saved intent; source pickers and capability-specific settings arrive in Vis4–Vis8 through registration points. Concrete production providers and presenters are absent in Vis3 and clearly unavailable; no fabricated chart data is shipped.

Use typed reactive forms, 650 ms serialized autosave, submitted-revision acknowledgements, and retained newer input. Normalize for comparison while retaining equivalent raw text during reconciliation. Merge name, title and legend independently; conservatively group interconnected sources/series/chart/period/comparison. Invalid input stays local; coherent incomplete/unavailable intent can save. Linked consumers see committed intent only.

Distinguish rejected persistence, conflicting authoritative snapshots, and committed-but-unpublished state. Recover the latter by publication/read, never mutation replay. One async navigation preflight owns portal review for both route guards and shell account/scope changes, without changing existing editor policies. Valid pending edits flush; invalid/failed/conflicting edits offer Stay, applicable Retry/Review, and explicit Discard. Running writes block destructive transitions. Protect unresolved session drafts with the shared conditional unload listener; no durable draft journal is added.

## Recovery and preview

Same-scope duplication uses Vis2's duplicate command. Cross-scope duplication uses a reviewed create proposal with independent identity, explicit destination, retained settings and listed cleared dependencies; never map by name. Reset a missing/blocked readable source only after explicit review, clearing the whole affected source selection and dependent series/chart references, retaining coherent reusable chart/appearance/date intent. Scatter repair clears only axis bindings whose series were removed; an unassigned axis stays setup-required and does not erase the selected Scatter chart. Readable transfer locks require acknowledgement and removal of unverified relationships. Unknown/unreadable formats stay read-only and backup-preserved, with diagnostics and confirmed deletion; no rename/copy/reset.

An externally deleted editor remains mounted with its draft. Save as new reviews local intent and allocates a fresh stable proposal. A deleted original facility requires explicit valid destination/scope review rather than automatic retargeting. Protected recovery proposals veto navigation before the workbench can replace their portal; check again after an awaited editor flush. Failed proposals can be canceled back to the original dirty draft, while committed-but-unpublished proposals require refresh recovery without mutation replay.

Preview is independent of save status. Only active previews request providers. Use one shared date context, exact chart support and domain compatibility checks. Abort and reject obsolete account/workspace/definition/edit/request responses. PreviewModule provides the registry in the feature injector so registrations from lazy V1 modules are visible. Providers/presenters and optional source editors are registrations; test adapters exercise ready, empty, loading/waiting, missing source, incompatible and calculation-error states. Production adapters and real-data chart acceptance remain downstream in Vis4–Vis8.

Use shared inventory/chart layers, portal-based `ConfirmationDialogComponent`, focus restoration, meaningful labels, accessible values alternatives, light/dark/high-contrast tokens, narrow windows and printing. No database schema, envelope version, calculation, v0, report, weather retrieval or IPC changes.

## Local implementation evidence

The six local slices include Dashboard naming and stepped Add visualization with concrete chart choices and multiple data sources. Native tests retain chart/source intent through reopen, reviewed repair/copy, duplication, deleted-draft recovery and Account/Facility backups. Invalid single-facility setup still blocks creation/copy until its sole facility is restored or the account is explicitly converted to a portfolio.

- Final focused checks: 334 domain/visualization unit tests and 35 Chromium tests passed. They include sole-facility copy restrictions, lazy feature registrations, and protected recovery controls through browser Back, retry, cancellation and an awaited-flush race.
- App, unit-spec and browser-spec TypeScript checks passed; local documentation links and whitespace checks passed. Production web compilation passed with existing component-budget and dependency-format warnings.
- Wide light and narrow dark/high-contrast screenshots were visually inspected. Chromium also checks all palette/mode combinations, overflow, keyboard operation and focus. Routed journeys use controlled command publication; real IndexedDB and backup behavior are verified separately. Full production-shell end-to-end acceptance remains outside this harness.
- Before review hardening, wider checks passed 4,368 fast tests and 544 Chromium tests, plus an Electron-target build. A later broad rerun was stopped at the user's request; final correction checks are deliberately focused. No Electron boundary changed and no further desktop check is selected or claimed.
- Restricted Angular runs exited 134 and were followed by passing normal-process checks. Combined tests exposed an eager chart-catalog snapshot, corrected using the neighboring lazy-read pattern. Two browser-fixture assertions were corrected: distinguish source cards from selection chips, and seed the valid meter relationship required by the legacy recovery case. Independent review then prompted focused ownership, injector and modal-navigation regressions.

Concrete providers/chart editors, real-data preview acceptance and starter recipe implementation remain downstream; this framework does not close #2904. PR preparation refreshes context-aware self-review and separate fresh no-history review records for the final comparisons. Human review, QA, publication and merge remain separate steps.

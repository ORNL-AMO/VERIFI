# V1 visualization Dashboard and workbench

This reference owns browsing, creation, editing, navigation, repair, and preview lifecycle. Use [foundation](v1-visualization-foundation.md) for meaning/runtime contracts and planned Home reuse, [persistence](v1-visualization-persistence.md) for durable commands/transfers, and [utility visualizations](v1-utility-visualizations.md) for implemented resources, line/bar controls, recipes, and capture.

## Dashboard and creation

Visualizations is enabled. Its account-owned Dashboard reuses resource cards, shared inventory detail levels, paging, sticky filters, and session browse restoration. Cards show derived ownership, categories, configured chart/period summaries, modification, and setup/reference status without requesting calculations. Search names, owners, and saved source labels; filter scope/data-source/setup/attention; sort modified, name, or attention. Folders, tags, favorites, thumbnails, bulk actions, and Recents remain pending.

Add uses typed decision transitions; the saved workbench retains its current source and chart settings layout until decision-section integration. Add collects Facilities, chart or preset, data categories, Meter selection method/resources, observation view, then name. Account entry starts at Facilities with live All; facility entry preselects that facility and starts at Chart, with Back to review Facilities. Single-facility accounts retain this explicit entry distinction and do not initialize hidden analysis pairs. Facilities use searchable checkbox cards with All Facilities first. Selecting every current facility promotes to live All, including future facilities; at least one facility remains. Double-click selects only that facility without first clearing its presentation.

Single decisions advance; multiple resources/categories require Continue. Reopening a completed decision preserves its descendants. Only actual dependency changes reset affected choices, with review when choices or incomplete input would be lost. Resources without readings remain selectable. Energy usage trend and Utility cost trend prefill this same flow, including Source, Meter group, and Individual meters paths. Cards distinguish facilities and retired meters. Meter setup defaults to Energy with calendarized monthly data; detailed measures/settings belong to the workbench.

The Add catalog offers Line, Bar, Scatter, Correlation, Heatmap, Donut, Treemap, and Sankey and the Meters, Predictors, Energy Use, and Analysis categories. Unimplemented combinations retain coherent setup intent without fabricated resources/series. Each category creates an independent local source identity. Energy Use-only setup defaults to latest saved fiscal year; other combinations use all saved history. Exact chart/source shapes and defaults belong to source contracts. There are no historical visualization decoders or upgrade adapters.

One creation proposal GUID survives failed save/retry and committed-publication recovery, then opens the saved workbench. Rename remains a simple form. Account routes use `visualization/dashboard` and `visualization/workbench/:visualizationGuid`. Facility entry filters Dashboard without retargeting intent. Session returns restore filters, paging/detail, scroll, and focus even when the new item falls outside them. Scope/account navigation resolves protected edits before changing context.

## Editing and guarded navigation

Facilities, Sources and Appearance sit beside a persistent preview; narrow screens stack controls first. Typed editors own name/title/legend, supported source/period fields, and registered chart settings. Unsupported combinations retain coherent intent with setup/unavailable feedback, never fabricated chart data.

Facilities offers live All and fixed subsets through the shared checklist. Checking every available facility promotes a user selection to All; hydration does not. Double-click selects only that facility. One fixed facility or one current All facility derives facility ownership; owner-relative units and fiscal periods follow that projection, while pinned settings and dates stay fixed. A reviewed same-identity command retains compatible choices and removes known excluded bindings. Incomplete child input must be resolved before changing facilities. Catalog changes during review invalidate the proposal; transaction validation prevents unreviewed pruning. Readable transferred charts can repair inclusion while ordinary source editing remains disabled. Add uses the same shared Facilities checkbox picker with independent draft progression.

Typed reactive forms use serialized debounced autosave and submitted-revision acknowledgements. Normalize comparisons while retaining equivalent raw text. Merge name, title, and legend independently; conservatively group interconnected source/series/chart/period/comparison changes. Acknowledgement updates the submitted baseline without replacing newer input. Invalid source/date fields remain protected during unrelated metadata saves; external changes to that configuration require explicit saved/local review. Linked consumers use committed definitions, never drafts.

Distinguish rejected persistence, conflicting authoritative snapshots, and committed-but-unpublished state. Recover the last through publication/read without mutation replay. One asynchronous navigation preflight owns portal review across route guards and shell account/scope actions. Valid pending edits flush; invalid/failed/conflicting input offers Stay, applicable Retry/Review, and explicit Discard. Running writes block destructive transitions. Shared conditional unload protection guards unresolved session drafts; no durable journal is added.

## Repair and deleted-draft recovery

Same-scope Duplicate uses independent identity. Cross-scope copying uses a reviewed stable creation proposal with explicit destination, retained reusable settings, and listed cleared dependencies; never map by name. In single-facility accounts, copying retained portfolio intent requires review into the sole facility.

Reset readable missing/blocked sources only after review. Clear the affected selection and dependent series/chart references while retaining coherent reusable appearance/date/chart intent. Scatter repair clears removed axis bindings without erasing its selected chart. Readable transfer locks require acknowledgement/removal of unverified relationships. Unknown/unreadable formats remain read-only and backup-preserved, with diagnostics and confirmed deletion, without rename/copy/reset.

Externally deleted editors remain mounted with drafts. Save as new reviews intent and retains a new stable proposal. Deleted facilities require explicit valid destination review. Protected recovery proposals veto navigation before their portal can be replaced, including after an awaited flush. Cancel rejected proposals back to the original dirty draft; committed proposals require refresh-only recovery. Discarding incomplete child fields always needs an explicit decision.

## Decision transitions and extension points

The pure `decisions` layer projects dependency effects before mutating intent. Add keeps its unsaved typed draft and step progression, then builds coherent intent through those transitions. Reopening/equivalent choices does not clear later decisions. Review is pinned to editor/draft/workspace identity; cancellation retains the previous choices. Source-owned resource/item projections remain independent of transition execution, so Dashboard summaries stay calculation-free. Reusable decision/resource picker primitives are available for the later workbench layout without changing its current host.

Future Predictor, Energy Use and Analysis creation extends typed draft/projection/transition responsibilities; categories currently retain explicit setup/unavailable boundaries. Provider/date/presenter composition stays separate from editor presentation. Existing source editor registration remains until the workbench adopts its explicit feature host branches; this slice introduces no generic editor framework.

## Preview and validation

Preview availability is independent of save status. Active previews alone request registered providers. Feature-injector registration supports lazy-loaded providers, presenters, and source editors. Use shared dates, exact settings support, domain compatibility, cancellation, and account/workspace/definition/edit/request identity; reject obsolete responses. Utility line/bar previews and supported underlying values are implemented. Other capabilities expose setup/unavailable states until their adapters arrive.

Use shared chart/inventory layers, shell-portal confirmations, focus restoration, accessible values, theme tokens, narrow layouts, and print support. Protect projections, ownership, retry identity, save/conflict/recovery races, invalid fields, reviewed copying/reset, unknown preservation, source loss, account/scope transitions, cancellation, and single-facility no-analysis-write behavior. Native storage/backup/reopen and keyboard/history/rendering journeys complement pure/editor tests. Select commands and broader gates through [testing policy](testing.md) and the validation planner. Remaining source/chart/capture coverage and full integration acceptance belong to the [phase plan](v1-visualizations-and-home-plan.md).
